Control de acceso a feria — Set y Map

Crea ControlFeria. Acreditaciones como F001 son únicas y se recuperan por código. Contrasta List, Set y Map; no hace falta usar las tres en producción.

  4. Clic derecho en src → New → Java Class → Main.

    }

Pulsa Run en el triángulo verde junto al método principal.

Checkpoint A: aparece Control de feria iniciado.

Paso 2 · Crear Asistente

  1. Clic derecho en src → New → Java Class → Asistente.
  2. Copia:
public class Asistente {
    private final String codigo;
    private final String nombre;

    public Asistente(String codigo, String nombre) {
        this.codigo = codigo;
        this.nombre = nombre;
    }

    public String getCodigo() { return codigo; }
    public String getNombre() { return nombre; }

    public String resumen() {
        return codigo + " - " + nombre;
    }
}

2. Elegir colección

Compara secuencia, unicidad y recuperación por clave.

Paso 1 · Observar List, Set y Map

Abre src/Main.java y reemplaza temporalmente su contenido por:

import java.util.ArrayList;
import java.util.HashSet;
import java.util.HashMap;
import java.util.List;
import java.util.Set;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        List<String> lista = new ArrayList<>();
        lista.add("F001");
        lista.add("F001"); // List permite duplicados
        System.out.println("List: " + lista.size());

        Set<String> conjunto = new HashSet<>();
        conjunto.add("F001");
        conjunto.add("F001"); // Set rechaza código repetido
        System.out.println("Set: " + conjunto.size());

        Map<String, String> indice = new HashMap<>();
        indice.put("F001", "Ana");
        System.out.println("Map F001: " + indice.get("F001"));
    }
}

Ejecuta y confirma:

List: 2
Set: 1
Map F001: Ana

Checkpoint A: identifica que List sirve para conservar una secuencia; Set, para unicidad; Map, para asociar código → objeto.

Paso 2 · Decidir la estructura del caso

El negocio exige un código único y búsqueda directa por código. Adoptaremos un solo Map<String, Asistente> como fuente de verdad. No añadiremos otro Set «por obligación», porque dos índices separados podrían desincronizarse.

Responde en dos líneas:

  1. ¿Por qué HashMap.put sin comprobación puede sobrescribir una inscripción?
  2. ¿Qué alternativa tiene Map para registrar solo si la clave no existe? Respuesta: putIfAbsent.

Checkpoint B: puedes justificar la decisión antes de programar y diferenciarla de la prueba introductoria de tres colecciones.

3. Registro consistente

Utiliza Map cuando corresponda; rechaza un código repetido sin reemplazar la asociación.

Paso 1 · Crear RegistroFeria

  1. En src, clic derecho → New → Java Class → RegistroFeria.
  2. Reemplaza el archivo completo:
import java.util.HashMap;
import java.util.Map;

public class RegistroFeria {
    private final Map<String, Asistente> asistentes = new HashMap<>();

    public boolean registrar(String codigo, String nombre) {
        if (codigo == null || codigo.isBlank()
                || nombre == null || nombre.isBlank()) {
            throw new IllegalArgumentException("Código y nombre obligatorios");
        }

        String clave = codigo.trim().toUpperCase();
        Asistente nuevo = new Asistente(clave, nombre.trim());

        // Nunca reemplaza un registro previo.
        return asistentes.putIfAbsent(clave, nuevo) == null;
    }

    public Asistente buscar(String codigo) {
        if (codigo == null) return null;
        return asistentes.get(codigo.trim().toUpperCase());
    }

    public boolean eliminar(String codigo) {
        if (codigo == null) return false;
        return asistentes.remove(codigo.trim().toUpperCase()) != null;
    }

    public int cantidad() { return asistentes.size(); }
}

Checkpoint A: el atributo asistentes es privado y utiliza Map<String, Asistente>. La clave siempre se normaliza con trim().toUpperCase(), así que f001 y F001 representan la misma acreditación.

Paso 2 · Prueba integrada desde Main

  1. Abre src/Main.java. Reemplaza el ejercicio exploratorio por:
public class Main {
    public static void main(String[] args) {
        RegistroFeria feria = new RegistroFeria();
        System.out.println(feria.registrar("F001", "Ana"));
        System.out.println(feria.registrar("F002", "Pedro"));
        System.out.println(feria.registrar("f001", "Otra persona"));
        System.out.println("Total: " + feria.cantidad());
        System.out.println(feria.buscar("f001").resumen());
        System.out.println("Eliminó F002: " + feria.eliminar("F002"));
        System.out.println("Final: " + feria.cantidad());
    }
}
  1. Ejecuta.

Checkpoint B: la consola debe mostrar true, true, false, Total: 2, F001 - Ana, Eliminó F002: true, Final: 1.

Paso 3 · Entender igualdad

No necesitas redefinir equals() ni hashCode() para este diseño porque las claves String determinan unicidad y búsqueda. Sí podría ser necesario si usaras un HashSet<Asistente>: entonces la clase necesitaría una definición coherente de igualdad basada en el código.

Checkpoint C: justifica por qué un Map es suficiente sin mantener un Set paralelo.
