Cápsulas persistentes — JavaFX, MVC y DAO

Proyecto autónomo de 90 min con esquema capsula_fx_db. CRUD visual, validación, confirmación y persistencia; no requiere el lab de consola. Ejecución real pendiente.

Preparación

Java 21 y Maven con conector MariaDB; usa usuario limitado y una base local desechable. JavaFX solo para la variante visual. Crea un proyecto autónomo. No reutilices una entrega de otro lab.

Lee Handbook de Academy si necesitas reforzar conceptos. La ejecución se realiza en tu equipo, no en el navegador.

Laboratorio autónomo de Academic Labs. Conserva tu proyecto, capturas y resultados; no incluyas credenciales ni datos personales.

Preparar el proyecto local

Clona el repositorio Academic Labs y abre la carpeta activities/capsules-javafx-dao-lab/codigo como proyecto Maven (en el preview utiliza la rama de este PR). Alternativamente descarga cada archivo enlazado y conserva exactamente su ruta dentro de codigo/. Usa una base de datos local desechable, nunca producción.

Ejecuta el esquema como administrador local una sola vez, y crea un usuario dedicado con una contraseña propia. Ejemplo para MariaDB (reemplaza el valor de ejemplo):

CREATE USER 'labs_practica'@'localhost' IDENTIFIED BY 'CAMBIA_ESTA_CLAVE';
GRANT SELECT, INSERT, UPDATE, DELETE ON capsula_fx_db.* TO 'labs_practica'@'localhost';

Configura DB_USER=labs_practica y DB_PASSWORD con tu clave local en el IDE o terminal, sin guardarlas en Git. En terminal, verifica java -version y mvn -version. Ejecuta desde la carpeta codigo. Estos archivos son una referencia didáctica todavía no validada con los runtimes externos.

1. Preparación y contrato

Configura esquema propio, contrato DAO e implementación.

Instala JDK 21, Maven, IntelliJ IDEA y MariaDB Server. Verifica java -version y mvn -version. En Windows comprueba el servicio MariaDB en services.msc. Abre el cliente SQL como administrador local, ejecuta esquema.sql y crea un usuario de práctica con permisos SELECT, INSERT, UPDATE y DELETE solo sobre la base capsula_fx_db. No compartas contraseñas. En IntelliJ abre codigo/pom.xml como proyecto Maven y recarga dependencias. Configura DB_USER y DB_PASSWORD en Run > Edit Configurations > Environment variables; para terminal PowerShell usa $env:DB_USER y $env:DB_PASSWORD con tus valores locales. Configuración local.

Abre pom.xml, ejecuta esquema, crea modelo, conexión. Define interfaz CapsulaDao y implementación. Contrato declara operaciones; implementación contiene SQL. Compila con mvn compile. Crea un main temporal con CapsulaDao dao = new CapsulaDaoMySql(); imprime dao.listarTodos().size(). Checkpoint: 2 en una base nueva. No uses SQL en el controlador. En esta guía se usa Maven no modular; si tu proyecto tiene module-info, requiere javafx.controls, javafx.fxml, java.sql, y abre controller a javafx.fxml y model a javafx.base; revisa además el módulo del driver. 2. Vista y lectura

Carga filas en tabla con MVC, sin SQL en el controlador.

Crea FXML bajo src/main/resources/view y Main. Crea controlador: primero campos @FXML, initialize, cargar y error; para arrancar conserva métodos de botones vacíos temporalmente. fx:id coincide con campo y onAction con método. FXMLLoader inyecta campos antes de initialize. PropertyValueFactory usa getters del modelo, no columnas SQL. ObservableList notifica cambios de la tabla, no persiste. Ejecuta mvn javafx:run desde codigo. Checkpoint: dos filas visibles; selección carga título, mensaje y fecha. Si falla: ruta FXML, fx:controller, fx:id, getter y módulo. Referencias JavaFX.

3. Eventos y pruebas

Comprueba CRUD visual, cancelación, validaciones y persistencia con consulta independiente.

Completa controlador con guardar, actualizar, eliminar, limpiar, valido y formulario. Flujo: usuario → Controller → DAO → JDBC → MariaDB → lista → TableView. Valida campos vacíos, título máximo 100 y fecha no nula. Actualiza y elimina por ID seleccionado; confirma eliminación; captura SQLException y refresca solo tras escritura exitosa. No confundir índice visual con PK. Ejecuta mvn javafx:run.

Checkpoints

  • Guardar título con apóstrofo: aparece en tabla y SELECT.
  • Guardar vacío: alerta, ninguna fila nueva.
  • Seleccionar fila y modificar mensaje: persiste.
  • Eliminar sin selección: alerta; cancelar confirmación: sin cambios; aceptar: desaparece.
  • Reiniciar: mismo estado que SQL.
  • Detener servidor: error visible, no éxito falso.

Entrega capturas/salida SQL y explicación de responsabilidades MVC/DAO. El acceso JDBC síncrono es una simplificación docente; Task y transacciones son ampliaciones, no exigencias.
