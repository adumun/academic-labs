2. DAO JSON

Lee y guarda dos instrumentos con prueba aislada antes de usar la UI.

¿Qué vamos a conseguir?

Que una clase Java pueda escribir una lista de instrumentos en data/instrumentos.json y volver a leerla. Todavía no programaremos los botones.

package cl.adumun.inventario.dao;

import cl.adumun.inventario.model.Instrumento;
import com.fasterxml.jackson.core.type.TypeReference;
import com.fasterxml.jackson.databind.ObjectMapper;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

public final class JsonInstrumentoDao implements InstrumentoDao {
    private final Path archivo;
    private final ObjectMapper mapper = new ObjectMapper();

    public JsonInstrumentoDao(Path archivo) {
        this.archivo = archivo;
    }

    @Override
    public List<Instrumento> cargar() throws IOException {
        if (Files.notExists(archivo)) {
            return List.of();
        }
        return mapper.readValue(
                archivo.toFile(),
                new TypeReference<List<Instrumento>>() {}
        );
    }

    @Override
    public void guardar(List<Instrumento> instrumentos) throws IOException {
        Path directorio = archivo.toAbsolutePath().getParent();
        if (directorio != null) {
            Files.createDirectories(directorio);
        }
        // Para esta práctica pequeña guardamos la lista JSON completa.
        mapper.writerWithDefaultPrettyPrinter()
              .writeValue(archivo.toFile(), instrumentos);
    }
}

Checkpoint C: la clase implementa ambos métodos sin errores de compilación. Identifica que mapper.writeValue serializa y mapper.readValue deserializa.

3. Servicio

Prueba registro válido y duplicado rechazado; persistencia sin controladores.

Incremento observable: el modelo y DAO existentes se integran con reglas de registro; el archivo se escribe solo cuando los datos son válidos. Aún no se programa la interfaz.

Requisitos funcionales

  • Registrar un instrumento válido identificado por código.
  • Rechazar campos incompletos o códigos ya registrados.
  • Conservar en ObservableList solamente los datos confirmados por el DAO.

Requisitos técnicos

  • InventarioService utiliza InstrumentoDao, no ObjectMapper.
  • No existe escritura de archivos en controladores; aún no se crean controladores.
  • El servicio propaga IOException y entrega IllegalArgumentException para violaciones de negocio.

Paso 1 · Crear el servicio

  1. En Project abre src/main/java/cl/adumun/inventario/service.
  2. Clic derecho → New → Java Class → InventarioService.
  3. Pega todo este código:
package cl.adumun.inventario.service;

import cl.adumun.inventario.dao.InstrumentoDao;
import cl.adumun.inventario.model.Instrumento;
import javafx.collections.FXCollections;
import javafx.collections.ObservableList;

import java.io.IOException;
import java.util.ArrayList;

public class InventarioService {
    private final InstrumentoDao dao;
    private final ObservableList<Instrumento> datos =
            FXCollections.observableArrayList();

    public InventarioService(InstrumentoDao dao) { this.dao = dao; }

    public ObservableList<Instrumento> listar() { return datos; }

    public void cargar() throws IOException {
        var recuperados = dao.cargar();
        datos.setAll(recuperados);
    }

    public void registrar(String codigo, String nombre, String categoria)
            throws IOException {
        codigo = codigo == null ? "" : codigo.trim();
        nombre = nombre == null ? "" : nombre.trim();
        categoria = categoria == null ? "" : categoria.trim();

        if (codigo.isBlank() || nombre.isBlank() || categoria.isBlank()) {
            throw new IllegalArgumentException("Completa los tres campos");
        }
        for (Instrumento actual : datos) {
            if (actual.getCodigo().equalsIgnoreCase(codigo)) {
                throw new IllegalArgumentException("Código repetido");
            }
        }

        var nuevos = new ArrayList<>(datos);
        nuevos.add(new Instrumento(codigo, nombre, categoria));
        dao.guardar(nuevos);
        datos.setAll(nuevos);
    }
}

Checkpoint A: el servicio no contiene referencias a Stage, FXMLLoader ni ObjectMapper. Si se produce IOException, no agrega la nueva fila a la tabla.

package cl.adumun.inventario.controller;

import cl.adumun.inventario.model.Instrumento;
import cl.adumun.inventario.service.InventarioService;
import javafx.beans.property.ReadOnlyStringWrapper;
import javafx.fxml.FXML;
import javafx.scene.control.TableColumn;
import javafx.scene.control.TableView;

public class ListadoController {
    @FXML private TableView<Instrumento> tabla;
    @FXML private TableColumn<Instrumento, String> colCodigo;
    @FXML private TableColumn<Instrumento, String> colNombre;
    @FXML private TableColumn<Instrumento, String> colCategoria;
    private Runnable abrirFormulario;

    public void configurar(InventarioService servicio, Runnable abrirFormulario) {
        this.abrirFormulario = abrirFormulario;
        colCodigo.setCellValueFactory(c ->
                new ReadOnlyStringWrapper(c.getValue().getCodigo()));
        colNombre.setCellValueFactory(c ->
                new ReadOnlyStringWrapper(c.getValue().getNombre()));
        colCategoria.setCellValueFactory(c ->
                new ReadOnlyStringWrapper(c.getValue().getCategoria()));
        tabla.setItems(servicio.listar());
    }

    @FXML private void irFormulario() {
        abrirFormulario.run();
    }
}

package cl.adumun.inventario.controller;

import cl.adumun.inventario.service.InventarioService;
import javafx.fxml.FXML;
import javafx.scene.control.ComboBox;
import javafx.scene.control.Label;
import javafx.scene.control.TextField;
import java.io.IOException;

public class FormularioController {
    @FXML private TextField codigo;
    @FXML private TextField nombre;
    @FXML private ComboBox<String> categoria;
    @FXML private Label mensaje;
    private InventarioService servicio;
    private Runnable volverAlListado;

    @FXML private void initialize() {
        categoria.getItems().addAll("Guitarra", "Bajo", "Batería", "Teclado");
    }

    public void configurar(InventarioService servicio, Runnable volverAlListado) {
        this.servicio = servicio;
        this.volverAlListado = volverAlListado;
    }

    @FXML private void guardar() {
        try {
            servicio.registrar(codigo.getText(), nombre.getText(),
                    categoria.getValue());
            volverAlListado.run();
        } catch (IllegalArgumentException e) {
            mensaje.setText("Dato inválido: " + e.getMessage());
        } catch (IOException e) {
            mensaje.setText("No se pudo guardar el archivo: " + e.getMessage());
        }
    }

    @FXML private void volver() { volverAlListado.run(); }
}

Checkpoint C: el controlador no tiene Files.writeString, ObjectMapper ni Path.of. Ante una excepción se queda en el formulario y muestra el motivo.

Paso 5 · Conectar el arranque de la aplicación

  1. Abre la clase HelloApplication.java ya creada por IntelliJ. No crees otra Application.
  2. Reemplaza el archivo completo. El ejemplo presupone que listado.fxml y formulario.fxml están en el mismo paquete de recursos que el hello-view.fxml que creó el generador:
package cl.adumun.inventario;

import cl.adumun.inventario.controller.FormularioController;
import cl.adumun.inventario.controller.ListadoController;
import cl.adumun.inventario.dao.JsonInstrumentoDao;
import cl.adumun.inventario.service.InventarioService;
import javafx.application.Application;
import javafx.fxml.FXMLLoader;
import javafx.scene.Parent;
import javafx.scene.Scene;
import javafx.scene.control.Alert;
import javafx.stage.Stage;
import java.io.IOException;
import java.nio.file.Path;

public class HelloApplication extends Application {
    private final InventarioService servicio = new InventarioService(
            new JsonInstrumentoDao(Path.of("data", "instrumentos.json")));
    private Stage ventana;

    @Override public void start(Stage stage) {
        this.ventana = stage;
        stage.setTitle("Inventario musical");
        try {
            servicio.cargar();
            mostrarListado();
            stage.show();
        } catch (IOException e) {
            new Alert(Alert.AlertType.ERROR,
                    "Error al leer datos. Se conservará el archivo: "
                    + e.getMessage()).showAndWait();
        }
    }

    private void mostrarListado() throws IOException {
        FXMLLoader loader = new FXMLLoader(
                HelloApplication.class.getResource("listado.fxml"));
        Parent root = loader.load();
        ListadoController controlador = loader.getController();
        controlador.configurar(servicio, this::abrirFormulario);
        ventana.setScene(new Scene(root));
    }

    private void mostrarFormulario() throws IOException {
        FXMLLoader loader = new FXMLLoader(
                HelloApplication.class.getResource("formulario.fxml"));
        Parent root = loader.load();
        FormularioController controlador = loader.getController();
        controlador.configurar(servicio, this::abrirListado);
        ventana.setScene(new Scene(root));
    }

    private void abrirFormulario() {
        try { mostrarFormulario(); }
        catch (IOException e) { mostrarError(e); }
    }

    private void abrirListado() {
        try { mostrarListado(); }
        catch (IOException e) { mostrarError(e); }
    }

    private void mostrarError(IOException e) {
        new Alert(Alert.AlertType.ERROR,
                "No se pudo cargar la vista: " + e.getMessage()).showAndWait();
    }

    public static void main(String[] args) { launch(args); }
}
  1. Si HelloApplication.class.getResource("listado.fxml") devuelve null, tu archivo está en otra ubicación. Usa una ruta absoluta de classpath con /... o mueve los FXML a la carpeta real del paquete de Application.

5. Reinicio y recuperación

Dos filas sobreviven reinicio; campos inválidos no cambian archivo; JSON corrupto informa error y no se borra.

Paso 1 · Primera ejecución limpia

  1. Cierra la aplicación si sigue abierta.
  2. Dentro de la carpeta de trabajo identifica data/instrumentos.json. Si contiene datos de pruebas anteriores, haz una copia y luego elimina solamente el archivo de prueba (no el código).
  3. Vuelve a ejecutar HelloApplication desde IntelliJ.
  4. Comprueba que la tabla inicia vacía y no aparece una excepción.

Checkpoint A: la aplicación inicia correctamente sin JSON preexistente.

Paso 2 · Registrar y comprobar archivo

  1. Haz clic en Nuevo instrumento.
  2. Escribe G01, nombre Guitarra eléctrica, categoría Guitarra.
  3. Haz clic en Guardar; regresas a una tabla con una fila.
  4. Repite con B01, Bajo eléctrico, categoría Bajo.
  5. En el panel Project busca data/instrumentos.json. Si no aparece, usa la vista de proyecto y sincroniza el directorio; la ruta es relativa al directorio de ejecución.
  6. Abre el archivo: deben existir dos objetos con codigo, nombre y categoria.

Checkpoint B: tabla y archivo contienen dos instrumentos.

Paso 3 · Prueba decisiva: reiniciar

  1. Cierra totalmente la ventana de JavaFX.
  2. Comprueba en IntelliJ que terminó la ejecución anterior.
  3. Ejecuta de nuevo HelloApplication.
  4. No registres nada todavía: revisa la tabla inicial.

Checkpoint C: las mismas dos filas aparecen automáticamente. Esto demuestra deserialización desde JSON; no basta con que la tabla mostrara datos antes de cerrar.

Paso 4 · Probar errores sin perder datos

  1. Abre Nuevo instrumento.
  2. Prueba código g01 (misma identidad que G01) con otro nombre. Pulsa Guardar.
  3. Debe mostrar Código repetido y mantenerse en el formulario.
  4. Prueba código vacío, luego nombre vacío, luego categoría sin selección.
  5. Para comprobar JSON corrupto: cierra la aplicación, respalda el JSON válido, modifica temporalmente su copia de trabajo para que deje de ser JSON (por ejemplo {archivo-incompleto) y ejecuta.
  6. Debe mostrarse un error al iniciar sin reemplazar automáticamente el archivo corrupto. Restaura la copia válida para continuar.

Checkpoint D: entradas rechazadas no crean filas ni registros; el archivo inválido se conserva para poder diagnosticarlo.
