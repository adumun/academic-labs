Pedidos de cafetería — composición

Crea PedidosCafeteria. Pedido contiene código, Cliente y total; admite aumentos y descuentos válidos, sin total negativo. No requiere herencia, colecciones, excepciones ni persistencia.

JDK 21 e IDE o terminal; no requiere Maven ni JavaFX. Crea un proyecto autónomo. No reutilices una entrega de otro lab.

1. Cliente válido

Construye un Cliente con sus datos requeridos.

Paso 1 · Crear el proyecto

  1. Abre IntelliJ IDEA → File → New → Project.
  2. Elige Java, Name: PedidosCafeteria, JDK 21, Build system IntelliJ.
  3. Presiona Create y espera a que se prepare.
  4. En Project, clic derecho sobre src → New → Java Class → Main.
  5. Pega:
public class Main {
    public static void main(String[] args) {
        System.out.println("Pedidos de cafetería");
    }
}

Ejecuta con Run. Si src no está, créala y márcala como Sources Root.

Checkpoint A: se imprime Pedidos de cafetería. Detente si no puedes ejecutar.

Paso 2 · Crear Cliente.java

  1. Clic derecho sobre src → New → Java Class → Cliente.
  2. Reemplaza el archivo por:
public class Cliente {
    private final String rut;
    private final String nombre;
    private final String correo;

    public Cliente(String rut, String nombre, String correo) {
        this.rut = rut;
        this.nombre = nombre;
        this.correo = correo;
    }

    public String getRut() { return rut; }
    public String getNombre() { return nombre; }
    public String getCorreo() { return correo; }

    public String descripcion() {
        return nombre + " (" + rut + "), " + correo;
    }
}

Checkpoint B: IntelliJ reconoce los getters y no señala errores. Los atributos son privados y el constructor entrega los tres valores.

Paso 3 · Verificar dos objetos

Reemplaza temporalmente Main.java por:

public class Main {
    public static void main(String[] args) {
        Cliente ana = new Cliente("11111111-1", "Ana", "ana@ejemplo.cl");
        Cliente pedro = new Cliente("22222222-2", "Pedro", "pedro@ejemplo.cl");
        System.out.println(ana.descripcion());
        System.out.println(pedro.descripcion());
    }
}

Ejecuta y verifica que se imprimen dos líneas distintas. Los RUT son datos didácticos ficticios y no se validan en este laboratorio.

Checkpoint C: puedes explicar constructor, encapsulación y objetos distintos. En la siguiente etapa añadirás un Pedido que contiene una referencia a Cliente.

2. Colaboración

Crea Pedido que recibe Cliente, sin duplicar sus atributos.

Paso 1 · Crear Pedido.java

  1. Clic derecho en src → New → Java Class → Pedido.
  2. Pega el archivo:
public class Pedido {
    private final String codigo;
    private final Cliente cliente;
    private double total;

    public Pedido(String codigo, Cliente cliente) {
        this.codigo = codigo;
        this.cliente = cliente;
        this.total = 0;
    }

    public boolean agregarMonto(double monto) {
        if (monto <= 0) return false;
        total += monto;
        return true;
    }

    public boolean aplicarDescuento(double porcentaje) {
        if (porcentaje < 0 || porcentaje > 100) return false;
        total = total * (1 - porcentaje / 100);
        return true;
    }

    public double getTotal() { return total; }

    public String resumen() {
        return "Pedido " + codigo + " / " + cliente.getNombre()
                + " / total $" + total;
    }
}

Checkpoint A: la línea private final Cliente cliente; demuestra colaboración: Pedido conoce a un Cliente sin duplicar su rut, nombre y correo.

Paso 2 · Entender las reglas

En la clase, identifica:

  • El constructor inicializa total en cero.
  • agregarMonto rechaza cero o negativos mediante false.
  • aplicarDescuento admite porcentajes 0 a 100.
  • resumen utiliza el getter de Cliente, no accede directamente al atributo privado de esa clase.

Checkpoint B: la clase compila. Calcula a mano: añadir $8.000 y descontar 25% debe dejar $6.000.

3. Operaciones

Integra desde Main; agrega monto y aplica descuento.

Paso 1 · Reemplazar Main.java

Abre src/Main.java, Ctrl+A y pega:

public class Main {
    public static void main(String[] args) {
        Cliente ana = new Cliente("11111111-1", "Ana", "ana@ejemplo.cl");
        Pedido pedido = new Pedido("P001", ana);

        System.out.println(pedido.resumen());
        System.out.println("Agregar $8000: " + pedido.agregarMonto(8000));
        System.out.println("Descuento 25%: " + pedido.aplicarDescuento(25));
        System.out.println("Resultado: " + pedido.resumen());

        System.out.println("Descuento 150%: " + pedido.aplicarDescuento(150));
        System.out.println("Total final: " + pedido.getTotal());
    }
}

Pulsa Run.

Checkpoint A: aparece un pedido inicial de total 0.0; las operaciones válidas devuelven true; el total pasa a 6000.0; el descuento 150% devuelve false y no lo modifica.

Paso 2 · Comparar responsabilidades

  1. Main decide el orden de operaciones.
  2. Cliente representa los datos del comprador.
  3. Pedido controla el monto, los descuentos y la referencia al cliente.

Pregunta: ¿qué ocurriría si Main modificara directamente pedido.total? No compila: el atributo es privado.

Checkpoint B: ejecutaste un caso válido y uno inválido sin errores. Explica por qué el objeto Pedido recibe Cliente en el constructor y no tres String duplicados.
