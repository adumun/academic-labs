PRIMERO · LECTURA OBLIGATORIA · 3 MIN

Entiende el desafío antes de programar

Esta es la única parte que necesitas leer completa antes de comenzar. El resto de la ayuda técnica queda disponible para cuando la necesites.

El contexto: Centro Cultural Estación Sur

El centro cultural organiza talleres presenciales y virtuales. Necesita una aplicación de escritorio que permita registrar actividades, consultar su programación y conservar la información para próximas ejecuciones.

Tu objetivo

Construir una aplicación JavaFX de una sola ventana. Trabajarás con formularios, selección de modalidad, una tabla de talleres, validaciones y persistencia JSON, aprovechando el modelo de dominio que ya está implementado.

Reglas que debes respetar

  • Utiliza las clases del modelo entregado; no reescribas sus reglas ni cálculos.
  • Mantén una sola ventana y separa las responsabilidades de vista, Controller y DAO/Repository.
  • Para persistencia JSON utiliza Jackson (ObjectMapper), no Gson.
  • El trabajo consiste en completar la interfaz y el acceso a datos; el proyecto base no contiene esas soluciones.

Cómo trabajar las cápsulas

Avanza en orden. Cada cápsula presenta un contexto, un objetivo, tareas concretas y una respuesta esperada que te permite comprobar el resultado.

Intenta resolver antes de abrir la pista. Si te atascas, úsala como orientación: no entrega el código completo. Marca el checkpoint y registra brevemente lo que comprobaste.

Importante: la ruta Maven es la referencia directa de las cápsulas. También puedes crear el proyecto con Gradle desde IntelliJ; si eliges esa alternativa, conserva el modelo de dominio y utiliza las tareas equivalentes de Gradle, sin mezclar configuraciones Maven y Gradle.

MATERIAL OPCIONAL

Ayuda técnica y recursos

No necesitas leer todo esto ahora. Abre únicamente el apartado que corresponda a tu entorno o al problema que estés resolviendo.

JavaFX no arranca en IntelliJ (Maven)

JavaFX no viene incluido en el JDK desde Java 11. Si ejecutas App.java directamente con una configuración Application, puede aparecer JavaFX runtime components are missing. Para este proyecto utiliza javafx:run desde Maven o la configuración compartida del ZIP; no necesitas agregar manualmente un SDK JavaFX al JDK.

Trabajo en WSL2
  • Guarda el proyecto en el filesystem Linux, por ejemplo ~/projects.
  • Utiliza JDK 21 y Maven/Gradle instalados en el mismo entorno WSL2.
  • Abre el proyecto con la integración WSL de IntelliJ. Para mostrar ventanas gráficas necesitas WSLg.
  • No mezcles herramientas de Windows con dependencias nativas descargadas para Linux, ni al revés.
¿Cuándo y cómo incorporar Jackson?

Jackson se incorpora cuando desarrolles la persistencia JSON, no para construir la ventana. Si elegiste Gradle, la guía alternativa muestra cómo declarar Jackson Databind tanto en build.gradle como en build.gradle.kts. En el código trabajarás con ObjectMapper.

Tu avance en la ruta0 de 10 cápsulas completadas
01

Conoce el proyecto que recibiste

Proyecto Maven, modelo existente y punto de partida

08 min

Contexto

El Centro Cultural Estación Sur ya tiene definido cómo representar sus talleres y cómo calcular el arancel de cada modalidad. Lo que falta es una aplicación gráfica que permita administrarlos.

Objetivo

Reconocer la estructura del proyecto base y comprender qué responsabilidades resuelve el modelo antes de comenzar a construir la interfaz.

Qué debes hacer

  • Abre el proyecto Maven y ejecútalo. Comprueba que la configuración inicial funciona.
  • Identifica la clase general de actividad y las dos clases especializadas.
  • Localiza los constructores, getters y el método que entrega el arancel calculado.
  • Revisa qué datos son comunes y cuáles corresponden solamente a cada modalidad.
  • No modifiques ni reemplaces las clases del modelo.

Respuesta esperada

El proyecto compila y arranca. Puedes explicar qué clase representa cada modalidad, qué datos necesita cada constructor y qué método del modelo debes consultar para mostrar el arancel. El modelo permanece sin modificaciones.

Necesito una pista para avanzar

Antes de programar, recorre los paquetes y abre las clases del modelo. Busca primero la relación de herencia y luego compara los atributos de la clase general con los de cada especialización. No necesitas conocer cómo se calcula internamente el arancel: necesitas reconocer qué método público lo entrega. Esa distinción evita duplicar reglas en el Controller y te permite aprovechar el trabajo que ya viene resuelto en el proyecto base.

Checkpoint de la cápsula

02

Construye la ventana de administración

Scene Builder, FXML y controles JavaFX

12 min

Contexto

El personal necesita administrar los talleres desde una única ventana. Debe poder ingresar datos, consultar los registros y recibir mensajes sobre cada operación.

Objetivo

Diseñar una vista FXML que organice el formulario, la tabla, las acciones y el área de mensajes en una sola pantalla.

Qué debes hacer

  • Crea o completa la vista principal utilizando Scene Builder.
  • Agrega un selector de modalidad, campos comunes y dos grupos de datos específicos.
  • Incorpora una TableView para consultar los talleres registrados.
  • Agrega los botones Registrar y Eliminar, además de un área para mensajes.
  • Asocia la vista con su Controller y carga el FXML desde la clase de arranque.

Respuesta esperada

Al ejecutar, se abre una sola ventana con todos los elementos solicitados. Los controles se ven ordenados y el FXML carga correctamente con su Controller asociado, aunque todavía no todas las acciones estén implementadas.

Necesito una pista para avanzar

Organiza primero la pantalla en zonas: formulario a un lado, tabla en el espacio principal y mensajes cerca de las acciones para que el usuario pueda reconocer el resultado. Asigna identificadores claros a los controles que necesitarás desde Java y comprueba que el Controller esté asociado al FXML. Si la vista no carga, revisa la ruta del recurso y la referencia al Controller antes de cambiar el diseño completo. Mantén todas las acciones dentro de la misma ventana.

Checkpoint de la cápsula

03

El selector debe mostrar los campos correctos

ComboBox, eventos y controles habilitados

10 min

Contexto

Un taller presencial y uno virtual no requieren exactamente la misma información. Mostrar todos los campos activos al mismo tiempo puede confundir al usuario y provocar registros incompletos.

Objetivo

Responder al cambio de modalidad y habilitar únicamente los controles específicos que correspondan a la opción seleccionada.

Qué debes hacer

  • Configura el selector con las dos modalidades del modelo.
  • Cuando se elija Presencial, habilita los controles propios de esa modalidad y deshabilita los de Virtual.
  • Cuando se elija Virtual, realiza el comportamiento inverso.
  • Al cambiar de modalidad, evita que valores de la opción anterior se utilicen accidentalmente en el nuevo registro.
  • Comprueba qué ocurre cuando todavía no se ha seleccionado una modalidad.

Respuesta esperada

Los controles específicos disponibles cambian de acuerdo con la modalidad elegida. Los campos deshabilitados no intervienen en el registro y la aplicación no intenta construir una actividad sin una selección válida.

Necesito una pista para avanzar

El selector puede notificar un cambio mediante un evento o listener. Desde ese punto, actualiza el estado de los grupos de controles. Te conviene agrupar visualmente los campos específicos para no tener que habilitar o deshabilitar cada uno de manera dispersa. Piensa también en los valores que quedan escritos al cambiar de opción: deshabilitar un campo no siempre significa que su contenido haya desaparecido, por lo que debes decidir cómo evitar que un dato antiguo contamine el siguiente registro.

Checkpoint de la cápsula

04

Haz que la tabla represente al modelo

TableView, TableColumn y ObservableList

12 min

Contexto

La administración necesita consultar los talleres registrados y distinguir su modalidad, nombre, duración, cupos y arancel. El valor debe provenir del modelo, no de un cálculo duplicado en la interfaz.

Objetivo

Conectar una TableView a una ObservableList y configurar sus columnas para presentar los datos de las actividades.

Qué debes hacer

  • Define las columnas para modalidad, nombre, duración, cupos y arancel.
  • Prepara una ObservableList que contenga las actividades que se mostrarán.
  • Conecta la tabla a esa colección.
  • Configura cada columna para obtener el atributo correspondiente desde el objeto.
  • Para el arancel, consulta el resultado que entrega el modelo.

Respuesta esperada

La tabla muestra correctamente los objetos de ambas modalidades. Cada columna presenta el atributo correspondiente y el arancel coincide con el valor calculado por el modelo. La tabla queda preparada para reflejar cambios en la colección.

Necesito una pista para avanzar

La tabla no debería ser la dueña de los datos: observa una colección que mantiene la aplicación. ObservableList permite que JavaFX reaccione cuando agregas o quitas elementos. Revisa el tipo genérico de cada TableColumn y cómo obtiene su valor desde el objeto. Para el arancel, evita reconstruir la fórmula en la vista; si el modelo ofrece un método para consultarlo, esa es la fuente que debes utilizar.

Checkpoint de la cápsula

05

Registra una actividad desde el formulario

Lectura de controles y creación de objetos del modelo

14 min

Contexto

La ventana ya permite ingresar información, pero todavía no transforma esos datos en una actividad que pueda administrar el centro cultural.

Objetivo

Implementar el evento Registrar para leer los controles, construir la especialización correcta del modelo y reflejar el nuevo objeto en la tabla.

Qué debes hacer

  • Implementa el manejador del botón Registrar.
  • Lee los datos comunes y los datos específicos de la modalidad seleccionada.
  • Crea el objeto utilizando el constructor correspondiente del modelo existente.
  • Incorpora el objeto a la colección observada por la tabla.
  • Muestra una confirmación en el área de mensajes y limpia el formulario solo cuando el registro haya resultado exitoso.

Respuesta esperada

Al registrar una actividad válida, aparece una nueva fila con sus datos y arancel. El mensaje confirma la operación y el formulario queda preparado para un nuevo ingreso. No se crea un objeto de una modalidad distinta de la seleccionada.

Necesito una pista para avanzar

El selector determina qué clase concreta debes instanciar. Antes de construir el objeto, reúne los valores comunes y solo los campos específicos que correspondan a esa modalidad. Comprueba el orden y los tipos que esperan los constructores del proyecto base. Mantén el evento acotado: leer datos, solicitar la creación del objeto, actualizar la colección y comunicar el resultado. Si algo falla, no limpies el formulario antes de saber que el registro fue exitoso.

Checkpoint de la cápsula

06

Valida sin castigar al usuario

Validación, excepciones y mensajes en pantalla

14 min

Contexto

Un dato vacío o un número mal ingresado no debe cerrar la aplicación ni dejar información inconsistente. La persona necesita saber qué corregir y conservar lo que ya había escrito.

Objetivo

Validar los datos del formulario, comunicar los problemas dentro de la ventana y mantener los valores ingresados cuando una operación no pueda completarse.

Qué debes hacer

  • Comprueba que exista una modalidad seleccionada y que los campos de texto obligatorios no estén vacíos ni contengan solo espacios.
  • Verifica que duración y cupos puedan convertirse al tipo numérico esperado y tengan valores válidos.
  • Revisa los campos específicos de la modalidad seleccionada.
  • Si el modelo rechaza los datos, captura el problema y muestra un mensaje comprensible.
  • Ante un error, no agregues la actividad, no limpies los campos y reemplaza el mensaje anterior por el nuevo.

Respuesta esperada

Los datos incorrectos no generan registros. El mensaje identifica el problema dentro de la ventana, los valores ingresados permanecen disponibles para corregirlos y la aplicación continúa funcionando sin depender de mensajes por consola.

Necesito una pista para avanzar

Conviene validar en etapas: primero la selección y los campos obligatorios; después las conversiones numéricas; finalmente, las reglas que ya conoce el modelo. Convertir texto a número puede producir una excepción si el contenido no tiene el formato esperado, así que controla ese caso. Evita mostrar solo un mensaje genérico: indica qué dato debe revisarse. Mantén separadas la validación y la limpieza del formulario; limpiar corresponde únicamente al camino exitoso.

Checkpoint de la cápsula

07

Elimina únicamente el elemento seleccionado

Selección de TableView y actualización del estado

10 min

Contexto

Una actividad puede cancelarse y debe dejar de aparecer en la programación. Sin embargo, la aplicación no debe eliminar nada si el usuario no ha seleccionado una fila.

Objetivo

Implementar la eliminación desde la selección actual de la tabla y comunicar el resultado mediante el área de mensajes.

Qué debes hacer

  • Implementa el evento del botón Eliminar.
  • Obtén el elemento seleccionado en la TableView.
  • Si no existe selección, informa la situación y no modifiques la colección.
  • Si existe selección, elimina ese objeto de la colección y confirma la operación.
  • Comprueba que la tabla se actualice sin reconstruir toda la ventana.

Respuesta esperada

Al seleccionar una fila y eliminarla, desaparece de la tabla. Si no hay selección, la aplicación informa que debe seleccionarse una actividad y conserva intactos todos los registros.

Necesito una pista para avanzar

La selección puede ser nula; no asumas que siempre existe un objeto elegido. Consulta la selección de la tabla antes de intentar eliminar. Si no hay elemento, termina la operación después de mostrar el mensaje. Si lo hay, trabaja con ese objeto y no con una posición fija o con el último elemento agregado. Al modificar la ObservableList, la tabla debería reflejar el cambio por sí misma.

Checkpoint de la cápsula

08

Separa la interfaz del acceso a archivos

MVC y DAO/Repository

12 min

Contexto

La aplicación ya registra y elimina talleres en memoria. Si el Controller también se encarga de abrir archivos y convertir JSON, terminará concentrando demasiadas responsabilidades.

Objetivo

Organizar la solución mediante MVC y definir una capa DAO/Repository responsable de leer y escribir la información.

Qué debes hacer

  • Revisa la distribución de paquetes y ubica vista, Controller y modelo.
  • Define un contrato DAO/Repository con operaciones para recuperar y guardar las actividades.
  • Prepara una implementación concreta que se encargará de trabajar con JSON.
  • Haz que el Controller coordine las acciones sin construir rutas ni manipular directamente el contenido de los archivos.
  • Evita trasladar o duplicar las reglas de cálculo que ya resuelve el modelo.

Respuesta esperada

Las responsabilidades quedan reconocibles: la vista presenta controles, el Controller coordina eventos, el modelo representa las actividades y el DAO/Repository concentra el acceso a los archivos. La aplicación sigue registrando y eliminando elementos en memoria.

Necesito una pista para avanzar

Piensa qué debería cambiar si mañana decides guardar los datos en otro formato. Si el Controller conoce ObjectMapper o los nombres de los archivos, ese cambio lo obligaría a modificarse. Un contrato DAO permite que el resto de la aplicación solicite operaciones sin depender de cómo se realizan. Mantén el modelo enfocado en representar y calcular; evita mover lógica de presentación o de archivos hacia esas clases.

Checkpoint de la cápsula

09

Guarda y recupera los talleres con Jackson

Maven, JSON y persistencia por modalidad

16 min

Contexto

La programación no puede desaparecer cuando se cierra la aplicación. El centro cultural necesita conservar por separado los talleres presenciales y virtuales.

Objetivo

Implementar la persistencia JSON mediante Jackson y conectar la carga inicial y el guardado automático con las operaciones de la aplicación.

Qué debes hacer

  • Agrega a Maven la dependencia Jackson disponible en el laboratorio y recarga el proyecto.
  • Implementa la lectura y escritura JSON dentro del DAO/Repository.
  • Utiliza archivos separados: talleres_presenciales.json y talleres_virtuales.json.
  • Al iniciar, carga ambos archivos y reúne los objetos en la colección que observa la tabla.
  • Después de registrar o eliminar, actualiza el archivo correspondiente sin pedir una acción adicional al usuario.
  • Si un archivo todavía no existe, inicia esa colección vacía.

Respuesta esperada

Los talleres de cada modalidad quedan guardados en su archivo JSON. Al iniciar, la tabla muestra los registros recuperados. Si los archivos no existen, la aplicación abre normalmente con la colección vacía. Registrar o eliminar actualiza la persistencia automáticamente.

Necesito una pista para avanzar

Primero confirma que Maven descargó la dependencia jackson-databind y que el proyecto puede utilizar ObjectMapper. Identifica el tipo concreto de objeto que corresponde a cada archivo: al leer una colección desde JSON, Jackson necesita información sobre el tipo de sus elementos. Luego separa la responsabilidad de cada archivo por modalidad, de modo que la escritura y la lectura conserven y reconstruyan las clases correctas. Para evitar que la interfaz conozca detalles de persistencia, invoca las operaciones desde la capa que coordina el caso de uso y deja la conversión JSON dentro del DAO. Distingue un archivo inexistente de un error real de lectura.

Checkpoint de la cápsula

10

Comprueba la aplicación como una persona usuaria

Pruebas integradas, reinicio y manejo de errores

12 min

Contexto

Una aplicación que funciona una vez no necesariamente está terminada. Hay que comprobar que sus operaciones mantienen la coherencia entre formulario, tabla y archivos, incluso después de cerrar el programa.

Objetivo

Ejecutar una secuencia de pruebas funcionales que permita detectar errores de integración antes de considerar terminada la aplicación.

Qué debes hacer

  • Inicia la aplicación sin archivos JSON previos y comprueba que abra con la tabla vacía.
  • Registra actividades de ambas modalidades y confirma que aparecen en la tabla y en sus archivos correspondientes.
  • Cierra completamente la aplicación y vuelve a abrirla: comprueba que los registros se recuperen.
  • Elimina una actividad seleccionada, reinicia y confirma que ya no aparezca.
  • Prueba un formulario incompleto y una conversión numérica inválida. Comprueba que el mensaje aparezca en pantalla y que los datos ingresados se conserven.
  • Revisa que los errores de lectura o escritura se comuniquen en la ventana y no queden únicamente en la consola.

Respuesta esperada

La aplicación inicia sin archivos previos, registra y elimina actividades, conserva los cambios después de reiniciar y comunica los errores de forma visible. La tabla y los archivos representan el mismo conjunto de actividades al finalizar las pruebas.

Necesito una pista para avanzar

Prueba el recorrido completo, no solo cada botón por separado. Un registro puede verse bien en la tabla y aun así no haberse guardado; por eso debes cerrar el proceso y volver a abrirlo. Después elimina un elemento y repite la comprobación. Para los errores, observa tres cosas: que la aplicación no se detenga, que el mensaje explique qué ocurrió y que los datos válidos que la persona ya había escrito no desaparezcan innecesariamente. Si algo falla, identifica primero en qué límite ocurrió: vista, modelo o persistencia.
