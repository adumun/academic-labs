Pokédex REST

Tu misión es conectar una aplicación Android nativa con PokéAPI. La interfaz y navegación inicial ya están preparadas; tú implementarás la comunicación HTTP y la transformación de respuestas JSON.

KotlinAndroid StudioJetpack ComposeGET · JSON

Objetivo

Implementar el consumo de una API REST pública desde Android, presentar un listado paginado de Pokémon y consultar el detalle de un recurso seleccionado.

01 · ListarGET de Pokémon con limit y offset.
02 · NavegarSeleccionar un elemento y abrir su detalle.
03 · DetallarConsultar el recurso individual.
04 · MejorarScroll infinito, errores y reintentos.

Recursos

API base: https://pokeapi.co/api/v2/

Listado inicial:

GET /pokemon?limit=20&offset=0

Detalle por nombre o identificador:

GET /pokemon/{id-o-nombre}
Documentación PokéAPIProbar listado JSON

Lo que recibes

  • Proyecto Android Studio con Kotlin y Jetpack Compose.
  • Pantallas de listado y detalle, navegación y componentes visuales.
  • Datos de muestra locales para verificar la interfaz sin conexión.
  • Modelos de presentación y puntos de integración identificados.
Importante: el Starter no incluye cliente HTTP, repositorio remoto ni solicitudes a PokéAPI. Implementarás esa parte como núcleo de la actividad.

Ruta de trabajo

  1. Abre el proyecto Starter en Android Studio y ejecútalo sin modificarlo.
  2. Identifica los datos de muestra y el contrato de presentación.
  3. Agrega permiso de Internet y configura un cliente HTTP.
  4. Define los modelos que representen la respuesta del listado y del detalle.
  5. Implementa la consulta GET del listado y reemplaza los datos de muestra.
  6. Implementa paginación con limit y offset, respetando next.
  7. Implementa la consulta del detalle al seleccionar un Pokémon.
  8. Agrega estados de carga, error, vacío y reintento.
  9. Como extensión, activa la carga incremental al acercarse al final de la lista.

Contrato de implementación

La interfaz espera una lista de elementos de presentación y un elemento seleccionado para el detalle. Conserva la UI y completa los puntos marcados con TODO(REST). No acoples las pantallas directamente a las clases de respuesta de PokéAPI.

Checkpoints

  • La primera página muestra 20 resultados y no duplica elementos al avanzar.
  • La navegación abre el Pokémon seleccionado, no un elemento fijo.
  • Un fallo de red muestra un mensaje y permite reintentar.
  • La paginación termina cuando la API no entrega una URL next.
  • La app conserva fluidez al desplazarse y no bloquea el hilo principal.

Entrega

  • Proyecto Android completo.
  • Capturas o breve grabación del listado, paginación y detalle.
  • DevLog breve: decisiones, dificultades y cómo las resolviste.

Duración referencial: 90 minutos. La extensión de scroll infinito puede desarrollarse como desafío adicional.
