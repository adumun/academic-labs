Cápsulas persistentes — JDBC sin GUI

Proyecto autónomo de consola de 90 min: título, mensaje y fecha. Consulta, inserta, actualiza y elimina por ID. No requiere proyecto previo ni interfaz gráfica. Fuentes de referencia; ejecución real pendiente.

Preparación

Java 21 y Maven con conector MariaDB; usa usuario limitado y una base local desechable. JavaFX solo para la variante visual. Crea un proyecto autónomo. No reutilices una entrega de otro lab.

Lee Handbook de Academy si necesitas reforzar conceptos. La ejecución se realiza en tu equipo, no en el navegador.

Laboratorio autónomo de Academic Labs. Conserva tu proyecto, capturas y resultados; no incluyas credenciales ni datos personales.

Preparar el proyecto local

Clona el repositorio Academic Labs y abre la carpeta activities/persistent-capsules-jdbc-lab/codigo como proyecto Maven (en el preview utiliza la rama de este PR). Alternativamente descarga cada archivo enlazado y conserva exactamente su ruta dentro de codigo/. Usa una base de datos local desechable, nunca producción.

Ejecuta el esquema como administrador local una sola vez, y crea un usuario dedicado con una contraseña propia. Ejemplo para MariaDB (reemplaza el valor de ejemplo):

CREATE USER 'labs_practica'@'localhost' IDENTIFIED BY 'CAMBIA_ESTA_CLAVE';
GRANT SELECT, INSERT, UPDATE, DELETE ON capsula_db.* TO 'labs_practica'@'localhost';

Configura DB_USER=labs_practica y DB_PASSWORD con tu clave local en el IDE o terminal, sin guardarlas en Git. En terminal, verifica java -version y mvn -version. Ejecuta desde la carpeta codigo. Estos archivos son una referencia didáctica todavía no validada con los runtimes externos.

1. Preparación y conexión

Configura esquema desechable y prueba SELECT de conexión.

Instala JDK 21, Maven, IntelliJ IDEA y MariaDB Server. Verifica java -version y mvn -version. En Windows comprueba el servicio MariaDB en services.msc. Abre el cliente SQL como administrador local, ejecuta esquema.sql y crea un usuario de práctica con permisos SELECT, INSERT, UPDATE y DELETE solo sobre la base del lab. No compartas contraseñas. En IntelliJ abre codigo/pom.xml como proyecto Maven y recarga dependencias. Configura DB_USER y DB_PASSWORD en Run > Edit Configurations > Environment variables; para terminal PowerShell usa $env:DB_USER y $env:DB_PASSWORD con tus valores locales. Configuración local.

Ejecuta esquema SQL una vez; SELECT * FROM capsula debe mostrar dos filas en una base nueva. Crea pom.xml y DatabaseConnection. JDBC es la API, Connector/J el driver y MariaDB el servidor. URL jdbc:mariadb://localhost:3306/capsula_db. Crea TestConnection, ejecuta su main o desde codigo: mvn compile exec:java -Dexec.mainClass=app.TestConnection. Checkpoint: Conexión exitosa. Si falla: No suitable driver = dependencia; connection refused = servicio/puerto; access denied = credenciales/permisos; unknown database = esquema.

2. Modelo y lectura

Mapea dos filas a objetos con ResultSet.

Crea Capsula con atributos privados, constructor y getters. INT → int, VARCHAR/TEXT → String, DATE → LocalDate. En CapsulaDao implementa primero listarTodos: abre conexión, prepara SELECT, ejecuta executeQuery, recorre while(rs.next()), construye Capsula con getInt/getString/getDate().toLocalDate() y agrega a ArrayList. Copia los imports y solo el método de lectura en esta etapa. Crea un main temporal que imprima los títulos. Checkpoint: Mi futuro y Un recuerdo. ¿Qué cambia con if en lugar de while? Tip: cursor inicialmente antes de primera fila; no leer sin next. Los recursos se cierran con try-with-resources. Referencias JDBC.

3. CRUD y pruebas

Verifica insert, update y delete por ID mediante SELECT independiente. Conserva script SQL y código.

Completa CapsulaDao con insertar, actualizar y eliminar. Los ? se enlazan desde 1 y sin comillas; Date.valueOf convierte LocalDate. executeUpdate devuelve filas afectadas. UPDATE y DELETE deben filtrar por id. No concatenar valores SQL ni esconder SQLException.

Ejecuta TestDao desde IntelliJ o mvn compile exec:java -Dexec.mainClass=app.TestDao. Crea un registro de prueba con título único, recupera ID, edita mensaje, verifica lectura y elimina solo esa fila. Checkpoint: CRUD OK. Prueba además un título con apóstrofo, un ID inexistente y desconexión controlada. Verifica con SELECT * FROM capsula. Guarda evidencia de cada operación; no borres datos ajenos.
