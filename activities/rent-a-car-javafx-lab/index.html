1. Entorno JavaFX

Ejecuta el Hello! generado antes de modificar archivos. Revisa módulo si existe.

Punto de partida

No tienes un proyecto todavía. IntelliJ IDEA está instalado. Hoy vamos a crear una aplicación JavaFX desde New Project, comprobar que funciona y recién después modificarla.

Por qué importa: el asistente JavaFX de IntelliJ prepara las bibliotecas y un proyecto demostrativo ejecutable. No tiene sentido construir manualmente todo eso si el IDE ya sabe hacerlo.

Paso 1 · Comprueba el complemento JavaFX

  1. Abre IntelliJ IDEA.
  2. Si estás en un proyecto abierto, entra a File → Settings (en macOS, IntelliJ IDEA → Settings). También puedes usar Ctrl+Alt+S en Windows.
  3. En el menú izquierdo, haz clic en Plugins.
  4. Abre la pestaña Installed.
  5. Busca JavaFX y comprueba que esté Enabled.
  6. Si aparece deshabilitado, habilítalo y reinicia IntelliJ cuando te lo solicite.

¿Qué deberías comprobar? Al crear un proyecto aparece la opción JavaFX bajo Generators. Si ya la ves, el complemento está disponible.

Paso 2 · Abre el asistente correcto

  1. Si estás en la pantalla de bienvenida, presiona New Project.
  2. Si tienes otro proyecto abierto, usa File → New → Project….
  3. En la columna izquierda, NO selecciones Java.
  4. Baja a la sección Generators y haz clic en JavaFX (el elemento con su propio ícono).

Checkpoint: en el formulario de la derecha ves campos como Name, Location, Language, Build system, Group, Artifact y JDK.

Paso 3 · Completa cada campo

Usa estos valores. En algunas versiones el asistente coloca valores de ejemplo que debes reemplazar.

  1. Escribe RentACarJavaFX en Name.
  2. Elige la carpeta de destino en Location. Debajo de ese campo IntelliJ indica dónde quedará guardado; verifica que corresponda.
  3. Selecciona Java en Language.
  4. Selecciona Maven en Build system.
  5. Escribe el Group y Artifact de la tabla.
  6. En JDK selecciona una instalación de Java 21. Si únicamente ves 17, 27 u otra versión, abre el desplegable y utiliza Download JDK → versión 21; confirma la descarga. No uses JDK 27 solo porque venga seleccionado automáticamente.
  7. Puedes activar Create Git repository si ya quieres registrar cambios; no es obligatorio para ejecutar el laboratorio.
  8. Presiona Next, no Create, cuando el asistente ofrezca un siguiente paso.

¿El botón Next no aparece? Comprueba que seleccionaste JavaFX en Generators, no Java. Algunas pantallas requieren desplazarse hasta el pie del diálogo.

Paso 4 · Pantalla «Additional libraries» (no marques ninguna)

Después de presionar Next, IntelliJ muestra la pantalla Additional libraries. Aquí verás casillas como BootstrapFX, ControlsFX, FormsFX, FXGL, Ikonli, TilesFX y ValidatorFX.

  1. Deja todas las casillas desmarcadas, tal como aparecen inicialmente. No selecciones FormsFX aunque nuestro trabajo incluya un formulario.
  2. Comprueba que abajo se indique No dependencies added. Es lo esperado, no es un error.
  3. No busques FXML en esta lista: FXML forma parte de la plantilla JavaFX que estamos creando. Estas opciones son bibliotecas adicionales, no los controles básicos ni un requisito para usar FXML.
  4. Haz clic en CREATE.
  5. Espera mientras IntelliJ crea el proyecto e importa las dependencias Maven.

Resultado esperado: se abre el proyecto RentACarJavaFX con su aplicación JavaFX inicial. No necesitas volver atrás para marcar una biblioteca.

Si marcaste alguna por error: antes de pulsar CREATE, desmárcala y comprueba que vuelva a aparecer No dependencies added.

  1. Si IntelliJ pregunta dónde abrirlo, elige abrirlo en una nueva ventana cuando quieras mantener separado un proyecto anterior.
  2. Espera a que termine la importación Maven. La primera apertura puede descargar dependencias y demorar un poco.

Checkpoint: a la izquierda se ve el proyecto RentACarJavaFX. Si no aparece el panel, abre View → Tool Windows → Project (en Windows suele ser Alt+1).

Paso 5 · Reconoce lo que creó IntelliJ

  1. En el panel Project, expande src/main/java.
  2. Busca la clase de arranque, habitualmente HelloApplication.java.
  3. Busca HelloController.java junto a esa clase (o en su paquete).
  4. Expande src/main/resources y busca hello-view.fxml en el paquete de recursos.
  5. En la raíz comprueba la existencia de pom.xml.
  6. Puede existir module-info.java bajo src/main/java: no lo borres.
  7. Abre HelloApplication.java y mira su primera línea, por ejemplo:
package cl.adumun.rentacar;

Guarda ese nombre de paquete: es el que usaremos en la etapa 03. Si tu asistente creó otro paquete, usa el que realmente aparece en tu archivo, no inventes otro.

¡Muy importante! No reemplaces pom.xml, no agregues otra clase Application, no cambies module-info.java y no descargues un proyecto de ejemplo externo: IntelliJ ya generó una aplicación configurada.

¿El asistente creó otros nombres? Usa los nombres reales que aparecen en tu proyecto y ubica las tres funciones equivalentes: clase que extiende Application, clase controller y archivo FXML. Si no encuentras controller o FXML, revisa la estructura del proyecto generado y solicita ayuda indicando qué archivos aparecen; no selecciones FormsFX ni otra biblioteca adicional como solución.

Paso 6 · Ejecuta el proyecto generado SIN modificarlo

  1. Haz doble clic en HelloApplication.java.
  2. Busca el ícono de ejecución verde a la izquierda del método main (o junto a la clase).
  3. Haz clic en el ícono y selecciona Run 'HelloApplication.main()'.
  4. Espera la compilación y la descarga inicial de bibliotecas.
  5. Resultado esperado: aparece una ventana del ejemplo JavaFX generado por IntelliJ. Generalmente muestra un botón Hello!.
  6. Haz clic en el botón y verifica que el ejemplo reacciona según el código generado.
  7. Cierra la ventana.

¡Bien! Ya tienes una aplicación JavaFX funcionando, antes de escribir nuestro formulario.

¿No aparece el ícono verde? Comprueba que importó Maven y que IntelliJ reconoce JDK 21. También puedes ejecutar el objetivo javafx:run en View → Tool Windows → Maven → Plugins → javafx si el proyecto generado lo ofrece.

Paso 7 · Solución de bloqueos frecuentes

  • No aparece JavaFX en Generators: verifica Settings → Plugins → Installed → JavaFX y habilita el complemento.
  • Solo aparece JDK 27 en la lista: selecciona Download JDK → 21 en el desplegable.
  • Maven está descargando bibliotecas: espera; no cierres IntelliJ.
  • Cannot resolve symbol javafx: espera la importación, abre el panel Maven y haz clic en Reload All Maven Projects.
  • release version 21 not supported: entra a File → Project Structure → Project, selecciona SDK 21 y confirma en Maven Runner que también se utilice JDK 21.
  • No existe HelloController o hello-view.fxml: busca en src/main y comprueba los nombres reales creados por la plantilla. Si no aparecen, muestra al docente la estructura del proyecto. La pantalla Additional libraries no sirve para habilitar FXML.
  • Error de JavaFX runtime: utiliza la configuración Run generada por IntelliJ o el objetivo Maven javafx:run; no intentes resolverlo agregando VM options sin comprender la configuración existente.

2. Formulario

Crea patente, botón y mensaje en FXML; conserva nombres generados.

¿Qué vamos a lograr?

La ventana inicial de IntelliJ ya funciona. No crearemos otro proyecto ni otro FXML: vamos a modificar el archivo que el generador creó para cambiar el ejemplo «Hello!» por nuestro formulario de patente.

Paso 1 · Encuentra el FXML que ya existe

  1. En IntelliJ, abre View → Tool Windows → Project.
  2. Despliega src/main/resources.
  3. Busca hello-view.fxml, generalmente dentro de una carpeta con el nombre del paquete.
  4. Ábrelo con doble clic y observa que contiene el botón del ejemplo.
  5. En HelloApplication.java, identifica dónde aparece FXMLLoader: carga ese archivo FXML.

Checkpoint: sabes qué archivo FXML se muestra al ejecutar. No crees MainView.fxml ni otro FXML paralelo.

Paso 2 · Decide cómo lo editarás

Ruta recomendada, sin instalaciones adicionales: editar hello-view.fxml como texto en IntelliJ, copiando la vista completa del paso 3.

Si tienes Scene Builder instalado: abre el FXML con Scene Builder mediante las opciones del IDE (si aparecen) o desde Scene Builder → File → Open y selecciona el archivo. Usa el panel de jerarquía para construir VBox, un título Label, TextField, Button y un Label de resultado. Luego guarda el archivo. La vista debe quedar equivalente al paso 3.

Para estudiantes que recién comienzan: la ruta de texto está completamente documentada y es suficiente; Scene Builder puede utilizarse después para practicar la edición visual.

Paso 3 · Escribe la vista completa sin controlador por ahora

  1. Selecciona la pestaña que muestra hello-view.fxml como código.
  2. Presiona Ctrl+A y pega lo siguiente (reemplaza todo el contenido).
  3. Guarda con Ctrl+S.
<?xml version="1.0" encoding="UTF-8"?>
<?import javafx.geometry.Insets?>
<?import javafx.scene.control.Button?>
<?import javafx.scene.control.Label?>
<?import javafx.scene.control.TextField?>
<?import javafx.scene.layout.VBox?>

<VBox alignment="CENTER" spacing="12"
      xmlns="http://javafx.com/javafx/21"
      xmlns:fx="http://javafx.com/fxml/1">
    <padding>
        <Insets top="16" right="16" bottom="16" left="16"/>
    </padding>
    <Label text="Registro de vehículo disponible"/>
    <TextField fx:id="patenteField" promptText="Patente del vehículo"/>
    <Button text="Registrar"/>
    <Label fx:id="resultadoLabel" text="Completa el formulario"/>
</VBox>

¿Qué hace cada elemento? VBox pone los controles uno bajo el otro; el primer Label es el título; TextField permite escribir; Button representa el registro; el último Label mostrará mensajes.

¿Por qué aún no existe fx:controller ni onAction? En esta etapa queremos comprobar primero que se dibuja la pantalla; conectaremos la acción después de escribir nuestro Controller en la etapa 03.

Paso 4 · Ejecuta la ventana modificada

  1. Guarda el archivo FXML.
  2. Abre HelloApplication.java.
  3. Haz clic en el ícono verde junto a main → Run 'HelloApplication.main()'.
  4. Deberías ver: el título «Registro de vehículo disponible», una entrada con pista «Patente del vehículo», el botón Registrar y el texto «Completa el formulario».
  5. Escribe cualquier patente de prueba y haz clic. El botón no hace nada todavía; eso es normal.

Si todavía aparece «Hello!»: verifica que editaste el FXML que carga la clase Application; mira el nombre de archivo dentro de getResource(...) y vuelve al paso 1.

Si algo falla

  • Location is not set: el nombre del archivo FXML o su ubicación ya no coincide con la ruta que carga HelloApplication.
  • LoadException: comprueba que copiaste el XML completo y que todavía no agregaste un fx:controller o onAction incorrecto.
  • No se actualiza la ventana: guarda, detén la ejecución anterior y vuelve a ejecutar HelloApplication.main().
  • El FXML se abre en Scene Builder en vez de mostrar código: busca la pestaña Text/Editor o usa Open in → Editor, dependiendo de tu versión de IntelliJ.

3. Evento y modelo

Conecta Controller al objeto Vehiculo, sin acoplar modelo a JavaFX.

Cómo funciona lo que construirás

Al hacer clic en Registrar: vista FXML → controlador → constructor de Vehiculo → mensaje en la vista. El constructor es responsable de rechazar patentes vacías, aunque no se use JavaFX.

Paso 1 · Identifica el paquete generado

  1. Abre HelloController.java en IntelliJ.
  2. Copia el nombre del paquete que aparece en la primera línea package ...;. Usaremos ese mismo paquete para Vehiculo y el controlador.
  3. En el ejemplo del laboratorio se muestra cl.adumun.rentacar. Si IntelliJ creó otro nombre, cambia la línea package de los ejemplos y el atributo fx:controller por el paquete real.

> Mantendremos el modelo en el mismo paquete del controlador para no introducir configuración modular extra. Es una simplificación didáctica de esta primera clase JavaFX.

Paso 2 · Crea la clase Vehiculo

  1. En el panel Project, busca el paquete donde existe HelloController.java.
  2. Haz clic derecho sobre ese paquete → New → Java Class.
  3. Escribe Vehiculo y presiona Enter.
  4. Sustituye el contenido de Vehiculo.java por el siguiente código. Conserva el package real de tu proyecto:
package cl.adumun.rentacar;

public final class Vehiculo {
    private final String patente;

    public Vehiculo(String patente) {
        if (patente == null || patente.isBlank()) {
            throw new IllegalArgumentException("La patente no puede estar vacía");
        }
        this.patente = patente.trim().toUpperCase();
    }

    public String getPatente() {
        return patente;
    }
}

Entiende lo que acabas de hacer: private protege el dato, final impide reasignarlo, el constructor evita nombres vacíos y trim().toUpperCase() quita espacios exteriores y transforma la patente a mayúsculas. getPatente() permite consultar el resultado.

Checkpoint pequeño: IntelliJ no marca Vehiculo.java con errores de compilación.

Paso 3 · Modifica el HelloController generado

  1. Abre el HelloController.java que creó IntelliJ. No crees otro Controller en paralelo.
  2. Selecciona su contenido y reemplázalo por el siguiente. Conserva el mismo paquete real del paso 1:
package cl.adumun.rentacar;

import javafx.fxml.FXML;
import javafx.scene.control.Label;
import javafx.scene.control.TextField;

public class HelloController {
    @FXML private TextField patenteField;
    @FXML private Label resultadoLabel;

    @FXML
    private void registrar() {
        try {
            Vehiculo vehiculo = new Vehiculo(patenteField.getText());
            resultadoLabel.setText("Vehículo disponible: " + vehiculo.getPatente());
        } catch (IllegalArgumentException exception) {
            resultadoLabel.setText(exception.getMessage());
        }
    }
}

¿Qué significa? @FXML conecta atributos y métodos del controlador con FXML; getText() lee la patente; new Vehiculo(...) valida; setText() muestra el resultado. Si la patente está vacía, el bloque catch presenta un aviso en vez de detener la aplicación.

Paso 4 · Conecta el FXML con ese Controller

  1. En IntelliJ abre hello-view.fxml.
  2. Busca la etiqueta inicial <VBox ...>.
  3. Agrégale el atributo fx:controller con el paquete que viste en HelloController.java, por ejemplo:
fx:controller="cl.adumun.rentacar.HelloController"
  1. Busca el botón Registrar y agrega el atributo onAction="#registrar", de manera que quede:
<Button text="Registrar" onAction="#registrar"/>
  1. Comprueba que el TextField tenga fx:id="patenteField" y el Label de resultado tenga fx:id="resultadoLabel".
  2. Guarda todos los archivos.

Si usas Scene Builder: selecciona la raíz VBox y escribe la clase del controlador en Controller class; luego selecciona el botón y escribe #registrar en On Action. Guarda.

No escribas un nombre de controlador distinto al de la clase Java: ambos deben coincidir.

Paso 5 · Ejecuta y comprueba

  1. Abre HelloApplication.java.
  2. Haz clic en el ícono verde junto a main → Run.
  3. Escribe ABCD12 y pulsa Registrar.
  4. Resultado esperado: Vehículo disponible: ABCD12.
  5. Borra el campo y pulsa Registrar.
  6. Resultado esperado: La patente no puede estar vacía. La ventana sigue abierta.
  7. Escribe abcd12 y confirma que la pantalla muestra ABCD12.

Si algo falla

  • LoadException por controlador: copia literalmente el valor de package de HelloController.java y añade .HelloController en fx:controller.
  • Error con module-info.java o acceso reflectivo: si el proyecto tiene module-info.java, revisa que el paquete del Controller figure en una directiva opens ... to javafx.fxml;. Si está en el mismo paquete generado, normalmente IntelliJ ya lo dejó configurado; no borres ese archivo.
  • NullPointerException tras hacer clic: revisa que patenteField y resultadoLabel coincidan letra por letra en Java y fx:id de FXML.
  • Error onAction='#registrar': comprueba que el método se llama registrar y está anotado con @FXML.
  • Sigue saliendo Hello!: tal vez ejecutas otro proyecto o no guardaste hello-view.fxml. Vuelve al checkpoint anterior.

Parte B · Desafío autónomo (después de completar el mínimo)

Agrega la marca del vehículo

  1. Abre hello-view.fxml.
  2. Bajo el TextField de patente, agrega un segundo TextField con fx:id="marcaField" y promptText="Marca del vehículo".
  3. Guarda y ejecuta: ya deberías ver los dos campos.
  4. En Vehiculo.java, agrega private final String marca;.
  5. Cambia el constructor para recibir (String patente, String marca); valida que ninguno esté vacío, guarda marca.trim() y crea getMarca().
  6. En HelloController.java, agrega @FXML private TextField marcaField;.
  7. Cambia la creación por new Vehiculo(patenteField.getText(), marcaField.getText()).
  8. Ajusta resultadoLabel.setText(...) para mostrar patente y marca.
  9. Ejecuta el programa y verifica el caso correcto, la marca vacía y la patente vacía.
  10. Checkpoint: muestra ambos datos solo cuando los dos campos son válidos.

Si IntelliJ muestra error de argumentos: es normal después de cambiar la firma del constructor. Busca new Vehiculo(...) y asegúrate de pasar dos argumentos.

Agrega un botón Limpiar

  1. En hello-view.fxml, debajo del botón Registrar agrega:
<Button text="Limpiar" onAction="#limpiar"/>
  1. En HelloController.java, agrega el método:
@FXML
private void limpiar() {
    patenteField.clear();
    marcaField.clear();
    resultadoLabel.setText("Completa el formulario");
}
  1. Ejecuta y prueba: escribe patente y marca, pulsa Limpiar y confirma que ambos campos quedan vacíos.
  2. Importante: este fragmento supone que completaste el desafío de marca. Si todavía no añadiste marcaField, elimina esa línea del método.
