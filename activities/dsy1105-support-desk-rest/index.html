Support Desk REST

Construye el cliente móvil de un sistema de tickets de soporte. Recibirás una interfaz Android Starter y un backend REST completo; tu desafío es implementar la integración entre ambos.

KotlinJetpack ComposeSpring BootH2CRUD

Objetivo

Consumir una API REST propia desde Android, enviar y recibir JSON, interpretar códigos HTTP y mantener la interfaz sincronizada con el servidor.

GETListar tickets y consultar detalle.
POSTCrear un ticket.
PUT / PATCHEditar ticket y cambiar estado.
DELETEEliminar un ticket.

Proyectos entregados

  • Android Starter: pantallas Compose, navegación, formularios y datos locales de muestra. No contiene cliente HTTP ni consumo REST.
  • Support Desk API: aplicación Spring Boot terminada, H2, datos iniciales, validaciones, manejo de errores y Swagger UI.
Tu responsabilidad: implementar la conexión y el consumo desde Android. No necesitas desarrollar ni modificar el backend.

Contrato REST

MétodoRutaResultado
GET/api/ticketsLista de tickets
GET/api/tickets/{id}Detalle
POST/api/ticketsCreación (201)
PUT/api/tickets/{id}Actualización completa
PATCH/api/tickets/{id}/statusCambio de estado
DELETE/api/tickets/{id}Eliminación (204)

Levantar el backend

  1. Abre el proyecto support-desk-api con Java 17 o la versión indicada en su README.
  2. Ejecuta ./mvnw spring-boot:run (Windows: mvnw.cmd spring-boot:run).
  3. Comprueba que responde en http://localhost:8080.
  4. Abre Swagger UI para explorar y probar los endpoints.
Emulador Android: http://10.0.2.2:8080
Dispositivo físico: http://IP_DEL_EQUIPO:8080
El emulador Android no utiliza localhost para llegar al computador anfitrión: utiliza 10.0.2.2. En un teléfono físico, ambos equipos deben estar en la misma red local y el firewall debe permitir el puerto 8080.

Ruta de trabajo

  1. Ejecuta el backend y prueba GET desde Swagger.
  2. Abre el Starter Android y reconoce las pantallas y el modelo de presentación.
  3. Implementa la configuración HTTP y los modelos JSON.
  4. Implementa GET de la colección y del detalle.
  5. Implementa POST con validación visual del formulario.
  6. Implementa PUT para editar un ticket.
  7. Implementa PATCH para cambiar su estado.
  8. Implementa DELETE y solicita confirmación antes de ejecutarlo.
  9. Actualiza la UI después de cada operación y muestra errores del servidor.

Validaciones que debes comprobar

  • Título obligatorio y con longitud máxima.
  • Descripción obligatoria y acotada.
  • Prioridad y estado deben pertenecer a los valores permitidos.
  • Un ID inexistente debe responder 404.
  • Una solicitud inválida debe responder 400 con detalle legible.
  • Un DELETE exitoso responde 204 sin cuerpo.

Entrega

  • Proyecto Android completo y funcional contra el backend.
  • Capturas de las cinco operaciones HTTP.
  • Evidencia de una validación fallida y su mensaje.
  • DevLog con decisiones y problemas de conectividad resueltos.

Duración referencial: 120 minutos.
